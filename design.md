# Bday_Aero Design System

Scope: `Bday_Aero` only. Not `Bday_Legacy`. This is the Phase 1 deliverable from the [Bday_Aero Deep Dive](https://claude.ai/code/artifact/a919b7bb-b695-45ea-b3ab-3ebcac377d3e) — replaces the untokenized, 3,757-line legacy SCSS carried over from the old theme with a real, documented token system.

Living document. Update it in the same commit as the token/CSS change it describes — a design doc written after the fact drifts from reality and stops being trusted. See "Migration status" at the bottom for what's tokenized so far vs. still on the legacy system.

## Reference inspiration

Screenshots and links supplied directly: nytimes.com, wsj.com, economist.com, semafor.com, businessday.co.za, plus four WordPress news-theme reference screenshots (a clean sidebar-led layout, a dense multi-rail "Fox Street" layout, a serif-mastheaded "New York" layout with dark-mode toggle, and a bold-headline "Fox Newspaper" layout). Patterns pulled from these are noted inline below rather than copied wholesale — per the deep dive's own §6, the goal is patterns, not pixels.

## 1. Color

Source: the supplied BusinessDay brand-accent palette (`Business Day Palette.dc.html`), used as-is for brand colors. Surface, border, and semantic colors are new — derived to work *with* that palette, not specified by it.

### Brand tokens (fixed, same meaning in both themes)

| Token | Hex | Source name | Use |
|---|---|---|---|
| `--bd-red` | `#E30613` | Signal Red | Primary accent — links, primary buttons, masthead accents |
| `--bd-red-strong` | `#8A0410` | Oxblood | Hover/pressed state for the above |
| `--bd-red-tint` | `#F3C9CB` | Blush | Light-mode subtle backgrounds, badges, active-state fills |
| `--bd-ink` | `#0A0A0A` | Ink | Brand-black reference (logo, not necessarily body text — see below) |
| `--bd-steel` | `#6E7175` | Steel | Brand-gray reference (muted/meta) |
| `--bd-paper` | `#FBFAF8` | Paper | Brand off-white reference |

### Light theme (default)

| Token | Value | Use |
|---|---|---|
| `--color-bg` | `#FBFAF8` (`--bd-paper`) | Page background |
| `--color-bg-raised` | `#FFFFFF` | Cards, the frosted-glass header's opaque fallback, modals |
| `--color-ink-1` | `#0A0A0A` (`--bd-ink`) | Headlines |
| `--color-ink-2` | `#2B2B2B` | Body copy — slightly softened off pure black for long-form Merriweather reading comfort |
| `--color-ink-3` | `#6E7175` (`--bd-steel`) | Meta, timestamps, captions, disabled text |
| `--color-border` | `#E7E2DD` | Rules, card borders, input borders — paper-tinted, not neutral gray |
| `--color-accent` | `#E30613` | Links, primary actions |
| `--color-accent-strong` | `#8A0410` | Hover/pressed |
| `--color-accent-tint` | `#F3C9CB` | Badge fills, subtle active backgrounds |
| `--color-focus-ring` | `#E30613` at 55% opacity, 2px outline | Keyboard focus — never remove, only restyle |

### Dark theme

Guarded per the three-state rule: bare `@media (prefers-color-scheme: dark)` for OS-driven dark, an explicit `[data-theme="dark"]` for a manual toggle (see §4, the New York reference screenshot's header includes exactly this toggle).

| Token | Value | Note |
|---|---|---|
| `--color-bg` | `#121110` | Warm near-black, not pure `#000` — pairs with paper's warmth inverted, avoids OLED-harsh contrast |
| `--color-bg-raised` | `#1C1A18` | Cards, header |
| `--color-ink-1` | `#F3F1EE` | Headlines — warm white, not pure `#FFF` |
| `--color-ink-2` | `#D6D2CC` | Body copy |
| `--color-ink-3` | `#948F88` | Meta, muted — lightened steel |
| `--color-border` | `#2E2B28` | Rules, borders |
| `--color-accent` | `#FF3B47` | Brightened from `#E30613` — the brand red under-contrasts on a near-black background at its light-mode value |
| `--color-accent-strong` | `#FF6169` | Dark mode "pressed" moves *brighter*, not darker — darkening oxblood further reads as muddy/invisible on a dark surface |
| `--color-accent-tint` | `rgba(227, 6, 19, 0.16)` | Blush doesn't translate directly to dark mode — a low-alpha accent overlay replaces the fixed pastel |

### Semantic color — deliberately separate from the accent

The brand accent is red, which is also the conventional color for "error/danger" — a real ambiguity if not handled explicitly. Semantic colors are their own token set, never aliased to `--color-accent`, and error states lean on icon/label as well as color, not color alone:

| Token | Light | Dark |
|---|---|---|
| `--color-success` | `#1E7A3D` | `#4ADE80` |
| `--color-warning` | `#B5790A` | `#DEA948` |
| `--color-danger` | `#C1121F` | `#F87171` |

`--color-danger` is a *different* red from `--bd-red` (cooler, less saturated) specifically so an error state and a "Subscribe" button are never visually interchangeable at a glance.

## 2. Typography

### Faces

| Role | Face | Fallback stack |
|---|---|---|
| Display / headlines | **Libre Baskerville** | `Georgia, "Times New Roman", serif` |
| Body / article copy | **Merriweather** | `Georgia, "Times New Roman", serif` |
| UI / nav / meta / buttons | **Inter** | `-apple-system, "Segoe UI", Helvetica, Arial, sans-serif` |
| Tabular / data | **JetBrains Mono** | `ui-monospace, SFMono-Regular, Menlo, monospace` |

Libre Baskerville and Merriweather are the two the brief specified. Inter and JetBrains Mono are a recommendation, not a given — they're already the fonts used in the supplied brand-accent palette file itself, so reusing them keeps the whole identity (palette doc + theme) consistent rather than introducing a fifth, unrelated typeface. Every reference screenshot follows this same pattern: a serif carries headline authority, a clean sans carries navigation/meta/buttons. Flag if a different UI face is wanted.

**Self-host, don't link Google Fonts.** Every performance decision earlier in this project (§1–§2 of the deep dive) has been about removing unnecessary external requests and render-blocking dependencies — a `<link>` to Google Fonts is exactly that class of cost, and it's avoidable: download the four faces' `.woff2` files once, serve them from the theme's own `assets/` via `@font-face`, matching how every other asset in this theme is already handled. `font-display: swap` on all four to avoid invisible-text-on-load.

### Type scale

A single scale shared by both faces, since Libre Baskerville and Merriweather are both used at headline vs. body sizes respectively — not two independent scales.

| Token | Size | Line-height | Typical use |
|---|---|---|---|
| `--text-xs` | `0.75rem` / 12px | 1.4 | Eyebrow labels, timestamps |
| `--text-sm` | `0.875rem` / 14px | 1.5 | Nav links, meta, captions |
| `--text-base` | `1rem` / 16px | 1.65 | Body copy default (Merriweather wants generous line-height for long-form reading) |
| `--text-lg` | `1.125rem` / 18px | 1.6 | Lead paragraph, pull quotes |
| `--text-xl` | `1.5rem` / 24px | 1.3 | Card headlines, subheadings |
| `--text-2xl` | `1.875rem` / 30px | 1.2 | Section headers |
| `--text-3xl` | `2.25rem` / 36px | 1.15 | Article headline (mobile) |
| `--text-4xl` | `3rem` / 48px | 1.1 | Article headline (desktop), homepage lead |
| `--text-5xl` | `3.75rem` / 60px | 1.05 | Masthead-scale moments only — used rarely |

Headline weight: Libre Baskerville Bold (700) at `--text-2xl` and above; Regular (400) below that, matching how the "New York" and "Fox Newspaper" reference screenshots both keep smaller headlines lighter-weight and reserve bold for the lead story.

## 3. Spacing, radius, shadow

Builds directly on the existing `_breakpoints.scss` (`$bp-mobile/tablet/desktop`, `bd-up`/`bd-down`/`bd-between` mixins) — new tokens follow its `bd-` naming, nothing renamed.

### Spacing

4px base unit, matching the fine-grained rules-and-columns density visible in every reference screenshot (thin dividers, tight meta rows):

`--space-1: 4px` · `--space-2: 8px` · `--space-3: 12px` · `--space-4: 16px` · `--space-5: 24px` · `--space-6: 32px` · `--space-7: 48px` · `--space-8: 64px` · `--space-9: 96px`

### Radius

The reference screenshots are almost entirely sharp-cornered — thin rules, square imagery, rectangular cards (all four screenshots; NYT/WSJ/Economist follow the same convention). Default content radius stays close to zero; only frosted-glass surfaces (§4) get real rounding, since softness reads correctly on a translucent panel in a way it doesn't on a flat editorial card.

`--radius-sm: 2px` (buttons, tags, thumbnails) · `--radius-md: 10px` (frosted-glass panels, modals only)

### Shadow

Two tiers, both restrained — editorial design leans on rules and whitespace for hierarchy, not drop shadows:

`--shadow-sm: 0 1px 2px rgba(10,10,10,0.06)` (cards) · `--shadow-md: 0 8px 24px rgba(10,10,10,0.12)` (modals, the frosted-glass header when scrolled)

## 4. Frosted glass

Requested as a prominent effect, explicitly not at the cost of visibility. Treated as a small, fixed set of tokens plus a hard rule on where it's allowed, not a free-floating style choice per component.

### Tokens

| Token | Light | Dark |
|---|---|---|
| `--glass-bg` | `rgba(255,255,255,0.72)` | `rgba(18,17,16,0.62)` |
| `--glass-border` | `rgba(10,10,10,0.08)` | `rgba(255,255,255,0.08)` |
| `--glass-blur` | `blur(16px)` | same |

```css
.bd-glass {
  background: var(--glass-bg);
  backdrop-filter: var(--glass-blur);
  -webkit-backdrop-filter: var(--glass-blur);
  border: 1px solid var(--glass-border);
}
```

### Where it's used — and where it isn't

**Used**: the sticky/condensed header once scrolled (see §5 — this is the primary, "prominent" application the brief asked for), the mobile nav drawer, the search overlay, modal scrims (subscribe/paywall prompts, the account flyout panel), and the mute/pause control overlay on featured-video cards from the deep dive's §9 spec — a strict improvement on the plain `rgba(0,0,0,0.55)` circles originally sketched there, now using the same system-wide glass token instead of a one-off value.

**Never used**: behind article body text, behind headline text on a busy photo without a scrim underneath, or anywhere `backdrop-filter` would sit over unpredictable user-uploaded imagery without a minimum-contrast fallback. Rule: any text rendered on `.bd-glass` must independently pass a 4.5:1 contrast check (body text) or 3:1 (large text/headlines) against the *worst-case* background it could sit over — checked at implementation time per component, not assumed from the token alone. `backdrop-filter` isn't supported in every browser context (e.g. some in-app webviews); `.bd-glass` always needs a solid-color fallback (`--color-bg-raised` at full opacity) behind the `@supports (backdrop-filter: blur(1px))` guard.

`prefers-reduced-transparency` (where supported) should fall back to the solid `--color-bg-raised` treatment — same accessibility posture already established for `prefers-reduced-motion` on the video cards.

## 5. Header pattern

Synthesized from the four reference screenshots plus general knowledge of nytimes.com/wsj.com/economist.com/semafor.com's own header conventions, not a copy of any single one.

**Utility bar** (thin, top, collapses on mobile): date, a "Today's Paper" quick link, sign-in/subscribe text links, social icons — the pattern present in three of the four reference screenshots ("Fox Street"'s ticker bar, "New York"'s and "Fox Newspaper"'s date-plus-subscribe bar).

**Masthead row**: hamburger (mobile) + search icon on the left, the BusinessDay wordmark centered, Subscribe (filled `--color-accent` button) + Login + a light/dark toggle on the right — the dark-mode toggle specifically mirrors the "New York" reference screenshot, and gives the dark-theme tokens in §1 a real, user-facing switch rather than OS-preference-only.

**Primary nav row**: section links, some with dropdowns (all four references show this), horizontally scrollable rather than wrapping on mobile.

**Sticky, condensed, glass on scroll**: past a scroll threshold, the header condenses (masthead + nav row collapse toward one compact bar) and switches to the `.bd-glass` treatment from §4 — this is the header's "prominent" frosted-glass moment, sitting over scrolling article/homepage content rather than a fixed opaque bar, while staying legible per the contrast rule above.

**Search**: expands as a glass-treated overlay rather than a separate page, consistent with the "New York" and "Fox Newspaper" references' search-icon-first pattern.

---

## 6. Accessibility guardrails (carried forward, not new)

Same posture established earlier in this project, restated here so it's in the one file people will actually check while building UI:

- `prefers-reduced-motion` respected everywhere, not just on video cards — no forced autoplay, no motion-heavy transitions on the glass header's condense/expand.
- Focus rings (`--color-focus-ring`) never removed, only restyled.
- Every token pairing (text-on-background, text-on-glass) gets checked for contrast at implementation time, not assumed correct from picking "the right token."

## Migration status

Legacy `assets/src/scss/style.scss` (3,757 lines, one Sass variable) stays as-is until components are migrated onto tokens one at a time. **Update as of Phase 15**: `body`'s own `font-family`/`color`/`background` are now token-driven (was `font-family: Lato` with no color/background at all, which is *why* the reader-reported "mode toggle only affects the header" bug existed — nothing else on the page consumed the tokens, so there was nothing for a mode switch to repaint). The bigger fix was `components/_premium.scss`'s five root Sass variables (`$bday-red`/`$bday-ink`/`$bday-muted`/`$bday-surface`/`$bday-border`) — this file is the *actual* primary component stylesheet for the rebuilt site (cards, headings, bylines, lists, hero), and its variables were literal hex values; pointing them at the CSS custom properties instead made the entire file theme-aware in one change, verified live across all three modes on both the homepage and an article page. The rest of legacy `style.scss` (and whatever `_premium.scss` doesn't cover) is still real, un-tracked migration work. Update this table as each part of the theme moves onto these tokens.

### Phase 15 — reader-directed header/footer/theming overhaul (in progress)

Triggered by direct reader feedback after seeing the site live: the header/footer still read as barely-changed from `Bday_Legacy`, the mode toggle was visibly broken beyond the header, and the theme needed a real logo instead of a bordered placeholder. Scope explicitly named "total overhaul of the entire frontend" — this entry covers what's actually done; the rest is tracked as open items below, not implied-done.

**Done, live-verified:**
- **Logo**: real BusinessDay lockup + icon supplied by the reader, cropped via `PIL` to remove an opaque grey/white border baked into the source PNG (the exact "reads as a box" problem flagged back in Phase 1) — `assets/src/public/images/bd-logo.png`/`bd-icon.png`, copied verbatim by Vite's `publicDir` like the fonts. Also wired as the `<link rel="icon">` favicon (there wasn't one before).
- **Header**, full rebuild on top of Phase 1's structure, synthesizing three supplied reference screenshots rather than copying one: a **dark utility bar** (WSJ's own device — fixed `--bd-ink`/`--bd-paper`, not the theme-relative tokens, so it stays legible and on-brand the same way in all three modes) carrying date/Today's Paper, a **world-clock strip** (Semafor's D.C./Riyadh/Beijing row, re-scoped to financial centres a Nigerian business audience actually trades against — Lagos/London/New York/Dubai, ticking client-side via `Intl.DateTimeFormat` so DST is handled correctly per zone), and the **three-state theme toggle**; a much taller, more deliberate **masthead row** (NYT's cue — the logo went from 32/40px to 38/48/58px across breakpoints) with the real logo now filling it properly; a WSJ-style **category nav row** with a red underline on hover/active instead of a plain color change.
- **Three-state theme system** (the reader's explicit bug report: light/dark existed, "warm" for blue-light reduction didn't, and the toggle only ever affected the header): new `:root[data-theme="warm"]` token block (`abstracts/_colors.scss`, sepia/warm-brown palette, deliberately explicit-only since no `prefers-warm` media feature exists to auto-select from), `script.js`'s toggle rewritten from a two-state flip to a three-state cycle (light → warm → dark → light), three icons in the header markup swapped via `[data-theme]` selectors.
- **Footer**, full rebuild — the old one was still Bootstrap `container`/`row`/`col-md-*` markup untouched since before the Bday_Aero rebuild started, including an unconditional CDN `<script src="bootstrap.bundle.min.js">` nothing else on the page used (confirmed zero references anywhere else, removed). New four-column editorial footer (About/Company/Legal/Quick Links/Support), same fixed-dark posture as the header's utility bar.

**Verified live**: homepage and an article page, screenshotted across all three theme states plus the scrolled/condensed header state and the mobile menu overlay; confirmed real headline/byline/excerpt text (not just chrome) stays legible in dark mode after the `_premium.scss` fix; confirmed the Bootstrap script tag is gone from the rendered page; PHP lint and the Phase 13 query-cache-discipline check both still pass.

**Explicitly not done yet** (the reader's other asks in the same message, sequenced as separate follow-on work, not silently folded into "done"):
- The login/create-account forms are SDK-rendered (`sdk/src/*.ts`, a separate package from this theme) and still carry the old visual style — untouched by this pass.
- The 25-category taxonomy list the reader supplied hasn't been created in WordPress or wired into the nav menu yet.
- No real BusinessDay.ng content has been pulled in — the homepage/article screenshots above are still the seeded placeholder copy from the preview pass, not real articles.
- Every other template (article body layout, archive/category listings, sidebars, comment area, default WP widgets visible in the article-page sidebar) is still on the legacy visual language — this pass covered header + footer + the site-wide theming bug specifically, not literally "every single part of the frontend," which remains real, large, sequenced work.

### Phase 16 — content, nav, auth-flyout, and remaining-template follow-through (done)

Everything Phase 15 explicitly deferred, done in sequence, each live-verified:

- **Podcast**: Spotify replaces the legacy hardcoded SoundCloud iframe entirely — new `_podcast_spotify_url` meta field (`addons/podcasts/includes/metabox.php`), a share-URL→embed-URL helper (`bday_podcast_spotify_embed_url()`), used by both `single-podcast.php` (audio-URL fallback retained for an episode with no Spotify listing yet) and a new homepage "Latest Episode" card — a play-facade over the episode art that lazy-injects the Spotify iframe only on click, never paying the embed cost for a visit that doesn't listen. Cartoon of the Day got a matching redesign: a "pinned" card (rotated frame, drop shadow, a pin dot) instead of a bare thumbnail link. Caught one real layout bug live: an eyebrow heading was marked up as `<span>` instead of `<h2>` — vertical padding/border on an inline element doesn't reserve box height, so the border painted in place and visually cut through the text below it.
- **Content**: created the reader's full 25-category list; pulled 95 real BusinessDay.ng articles via their own public REST API (`/wp-json/wp/v2`) — robots.txt-checked first, only their own already-published content, no third-party scrape. A first pass wrongly treated 11 categories as having no source match and fell back to a full-text search endpoint that reliably timed out; re-checked against the *complete* (paginated, 234-category) source list and found real matches for all but 2 (`start-up`, `ai`), cutting search fallback down accordingly. Imported with real images (sideloaded), correct categories, and original publish dates — caught a WordPress quirk where a `post_date`/`post_date_gmt` mismatch silently forces `post_status` to `future` regardless of what's explicitly passed, fixed on the affected rows. Homepage's editorial curation tags (`bdlead`/`bdrecent`/`bdothernews`) re-pointed from the original placeholder seed posts onto real imported articles.
- **Nav**: all 25 categories wired into both `main_menu` (masthead) and `secondary_menu` (mobile overlay) — verified wrapping cleanly across two rows at desktop width, no dropdown clipping.
- **Auth — the significant find**: a fully contract-compliant flyout login/account panel already existed (`sdk/src/nav-menu.ts` — inline login/register/OAuth, account-section drilldown, subscribe modal), built against a specific `data-aero-nav-*` markup contract. But `Bday_Aero`'s own `addons/aero-paywall/includes/class-nav-button.php` (the theme's copy, independent from the retired `connector-plugin`'s copy) had never been brought up to that contract — it emitted four bare `<a>` links with none of the trigger/panel/backdrop structure nav-menu.ts's own listeners look for, so the panel was silently non-functional on every real render. Ported the plugin's up-to-date markup over (same `aero-paywall-nav-*` classes the SDK's own `styles.ts` already styles theme-agnostically, so no new CSS was needed) and replaced `header.php`'s two `is_user_logged_in()`-based static links — itself a second bug, checking WordPress's own session auth rather than the JWT-cookie auth the SDK actually uses, so a real subscriber would always have read as logged out — with `bday_aero_nav_button()`. Also stood up dedicated `/login/` and `/create-account/` pages on an existing-but-unused minimal funnel template (`templates/template-funnel.php`, `header-minimal.php`/`footer-minimal.php`), wired through `Bday_Aero_Settings::login_page_url()`/`register_page_url()`, so those flows no longer render inside full article-page chrome. Light visual polish on top: `.aero-paywall-form-title` now uses the same Georgia serif already used by the flyout's own headline, for one consistent voice across both surfaces — deliberately not a deeper redesign, since `sdk/styles.ts` ships to every product built on this SDK, not just this theme, and the existing design was already close to the NYT flat-card reference.
- **New homepage section**: "The Briefing" — a Semafor-style, image-free numbered headline strip (Africa/World/Politics, `core/homepage/data.php`'s new `briefing` key via `tax_query`), sitting directly under the hero as the one deliberate text-only counterpoint to every other card-based section on the page.
- **Remaining templates**: the article page and sidebars were the real gap Phase 15 flagged and didn't touch.
  - **Sidebar/widgets**: every `register_sidebar()` call (`core/theme-setup.php`) wrapped widgets in `<span>` — an inline element around block content (lists, forms, images), invalid nesting that also meant `_premium.scss` had no block-level target to style at all, which is why the sidebar rendered as a completely unstyled default-WordPress markup dump. Fixed to `<div class="bday-widget">`/`<div class="bday-sidebar-widgets">`, then styled generically enough to cover both classic widgets (`.widget-title`) and this site's actual current sidebar content, which turned out to be block-based widgets (Gutenberg's Widgets screen — `wp-block-heading`, `wp-block-latest-posts`, `wp-block-search`) that never pass through `before_title`/`after_title` at all.
  - **Article page**: byline gained a bottom rule and bullet-separated meta; `bday_social_share_html()`'s share row (unstyled — the one legacy CSS block that targeted it addressed a different, no-longer-used markup shape) got real circular icon buttons; "Related News" and the author-bio box were restyled with arrow-bulleted links and proper heading treatment.
  - **Dark/warm-mode regression found live**: `.post-content` in legacy `style.scss` sets a hardcoded `color: #353535` — invisible against dark mode's near-black background, since an element selector with a literal color beats `body`'s own token-driven color. Same bug class as the root Sass variables fixed in Phase 15, same fix shape: overridden in `_premium.scss` (same specificity, later in the cascade) rather than editing the legacy file. `.bday-read-also`/`.bday-author-bio` had the same hardcoded-hex problem (`#fdedd7`) and are now token-driven (`--color-accent-tint`/`--color-bg-raised`).
  - **Archive/category listings and the podcast/cartoons CPT archives were checked and found already correct** — already running through the same `.bday-card-grid`/masonry-gallery system Phase 15's `_premium.scss` fix made theme-aware, nothing further needed.
- **Known follow-up, not built in this pass**: a reader-facing comment thread UI. The backend (`subscription-service`'s `Comment` model, cursor-paginated/depth-capped/captcha-gated, Phase 8) is done and live-verified, but nothing in this theme mounts it — same category of gap as the bookmark/follow/notification SDK components flagged in earlier phases. Building it is a new SDK module plus a mount point on `single-default.php`, not a template-styling pass, so it's named here rather than attempted inline.

### Phase 23 — bulk content seeding, and two real gating bugs found by actually exercising it (done)

Reader ask: populate the site with far more content so the theme's full surface is visible, then test the reader gating/monetization journey (anonymous → registered → subscriber) end to end. The second half of that ask is what actually mattered — running the real journey against real data surfaced two genuine paywall bugs that a code read would not have caught.

**Content seeding — synthetic, not scraped, and said so up front**: "posts from businessday.ng" was interpreted as *volume and shape*, not literal reproduction — republishing dozens of a live news site's actual articles into a database (even a private local one) is a copyright-reproduction question worth not walking into by default. Instead, a one-off seeder script (`wp eval-file`, not committed to the repo — a dev-data tool, not theme code) generated 102 original posts across all 25 real categories using sector-specific vocabulary pools (real Nigerian institutions/companies as subjects, plausible metrics/percentages) so the copy reads as topical business writing rather than lorem ipsum, each with a real featured image (reused from the 93 already in the media library), a mix of single/co-authored bylines, ~15% tagged Premium (for gating volume), ~10% Today's Paper, ~8% video-format. Homepage, category archives, and the Today's Paper page were all screenshotted afterward and render correctly at this volume.

**Bug 1 — any signed-in reader read as a subscriber**: `class-mobile-api.php`'s `resolve_entitlement()` (the WP REST route, `/wp-json/aeropaywall/v1/articles/{id}`, that the SDK actually calls to unlock an article — the authoritative path, not the render-time preview) treated *any* verified, non-staff reader JWT as `isSubscriber: true, stage: 'open'` unconditionally. It never read the token's own `subscriptionStatus` claim — the exact claim subscription-service's `EntitlementClaimsService` already bakes into every token it issues (login/register/refresh/checkout-verify), and the same claim the SDK's own `nav-sync.ts` already trusts client-side for UI state. Practical effect: registering a free account was functionally equivalent to subscribing — every premium article, unlimited, forever. **Bug 2 — the meter never actually locked anyone, for a completely different reason**: even after fixing Bug 1, a registered-but-unsubscribed reader still read unlimited premium content.
